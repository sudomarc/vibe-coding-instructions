# API Design Skill

Treat interfaces as contracts. Inspect existing versioning, validation, error envelopes, authentication, rate limits, observability, compatibility, and documentation. Prefer backwards-compatible evolution. Define failure behavior as carefully as success behavior.

References: `references/api-contracts.md`, `references/versioning.md`, `examples/api-change.md`.
